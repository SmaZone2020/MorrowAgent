# 05 UI/UX 设计规范（初稿）

## 1. 设计原则

- 学习任务优先：让用户明确现在学什么、为什么学。
- AI 与工具融合：对话、题目、图表和画板是同一学习流程的一部分。
- 渐进披露：复杂数据按需展开，避免 Dashboard 信息过载。
- 用户可控：AI 可以建议和动态规划，但重要目标变更需用户确认。
- 证据可见：掌握度、薄弱点和诊断结论应能查看依据。
- 跨平台一致：Windows 与 Android 保持核心概念一致，布局适配各自屏幕。

## 2. Dashboard 信息优先级

首屏优先展示：

1. 知识点掌握度。
2. 当前薄弱知识点。
3. 目标与进度。
4. 学习能力雷达图。
5. 学习趋势。

今日任务、待复习和 Lumi 建议可作为辅助卡片。

## 3. Lumi AI 工作台

- 消息流中允许插入交互卡片。
- 题目卡片内嵌画板，用户可独立伸缩画板。
- 卡片状态需清晰显示：未作答、编辑中、已提交、已分析、发生错误。
- AI 正在分析时提供明确反馈。
- 不应将每一次笔迹移动都触发模型请求；客户端可先聚合事件，在笔画完成、提交或阶段性节点回传。

## 4. 可访问性与反馈

- 重要状态不能只依赖颜色表达。
- 交互控件应有清晰点击区域和键盘/触控支持。
- 网络错误、模型错误和数据保存失败需分别提示。
- 用户提交前应能检查答案和思路。
- 诊断结论允许用户纠正。

## 5. 组件库

设计需使用 BeUI + TailwindCSS + Gravity Icons 的组合：

- https://beui.dev/llms.txt
- https://gravity-ui.com/zh/icons

正常情况下除了配色，不得修改组件库组件样式，不得擅自进行自绘组件或者自绘样式，优先使用组件库提供的元素，若无元素经过询问用户后再进行自绘。

图标与文字的组合需要优先考虑用户可视性，UI 设计时忌讳 [标题 + 副标题/简介] 的组合，只能使用标题。若该功能实在需要解释，改用 INFO 或 ？图标按钮，点击或 Hover 后显示信息。纯装饰性的说明文案直接删掉，不保留。

## 6. 配色规范

### 基础色板

| 名称 | 色值 | 用途 |
|---|---|---|
| 雾白 | `#EFEAE2` | 主色、页面底色 |
| 岩灰 | `#A59E95` | 强调色、次级分隔与描边 |
| 墨青 | `#384248` | 强调色、正文与主按钮 |

### 使用规则

- 只做浅色主题，不提供深色模式切换。
- 页面背景统一使用雾白，卡片使用雾白的更浅一阶，通过明度差区分层级，不使用高饱和色块。
- 墨青承担正文、主按钮和当前选中态；岩灰承担弱化描边、次级标记和禁用态。
- 强调色只用于需要用户注意的状态，不能大面积铺色。
- 状态色（成功、警告、危险、信息）仅用于语义反馈，且必须同时配合文字或图标，不能只靠颜色表达。

### 设计令牌

配色以 CSS 变量定义在 `src/styles/tokens.css`，Tailwind 通过 `@theme inline` 映射为 `bg-background`、`text-foreground`、`border-border` 等语义类名。业务代码只能使用语义类名，禁止直接写十六进制色值。

## 7. 窗口与外壳

- Windows 端使用无系统装饰窗口，标题栏由前端自绘。
- 自绘标题栏包含产品名、侧边栏开关和最小化/最大化/关闭控件，拖动区域通过 `data-tauri-drag-region` 声明。
- 无边框窗口会失去系统缩放边框，需在窗口四边与四角提供缩放热区并转发到系统缩放行为。
- 侧边栏收缩为图标栏时，分组标题、菜单文字、徽标和展开箭头全部隐藏，只保留图标，且图标之间不留分组间距。
- 收缩状态下的图标需保留可访问名称与悬浮提示，避免信息丢失。
- 收缩状态下点击带子菜单的菜单项，不展开侧边栏，而是在图标右侧弹出锚定的子项列表。
