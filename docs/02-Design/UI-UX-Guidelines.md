# 05 UI/UX 设计规范（初稿）

## 1. 设计原则

- 学习任务优先：让用户明确现在学什么、为什么学。
- AI 与工具融合：对话、题目、图表和画板是同一学习流程的一部分。
- 渐进披露：复杂数据按需展开，避免 Dashboard 信息过载。
- 用户可控：AI 可以建议和动态规划，但重要目标变更需用户确认。
- 证据可见：掌握度、薄弱点和诊断结论应能查看依据。
- 跨平台一致：Windows 与 Android 保持核心概念一致，布局适配各自屏幕。

## 2. Dashboard 信息优先级

首屏优先展示：

1. 知识点掌握度。
2. 当前薄弱知识点。
3. 目标与进度。
4. 学习能力雷达图。
5. 学习趋势。

今日任务、待复习和 Lumi 建议可作为辅助卡片。

## 3. Lumi AI 工作台

- 消息流中允许插入交互卡片。
- 题目卡片内嵌画板，用户可独立伸缩画板。
- 卡片状态需清晰显示：未作答、编辑中、已提交、已分析、发生错误。
- AI 正在分析时提供明确反馈。
- 不应将每一次笔迹移动都触发模型请求；客户端可先聚合事件，在笔画完成、提交或阶段性节点回传。

## 4. 可访问性与反馈

- 重要状态不能只依赖颜色表达。
- 交互控件应有清晰点击区域和键盘/触控支持。
- 网络错误、模型错误和数据保存失败需分别提示。
- 用户提交前应能检查答案和思路。
- 诊断结论允许用户纠正。

## 组件库

设计需使用BeUI+TailwindCSS+GravityIcon的组合

https://beui.dev/llms.txt

https://gravity-ui.com/zh/icons

正常情况下除了配色，不得修改组件库组件样式，不得擅自进行自绘组件或者自绘样式，优先使用组件库提供的元素，若无元素经过询问用户后再进行自绘。

图标与文字的组合需要优先考虑用户可视性，UI设计时忌讳[标题+副标题/简介]的组合，只得使用标题，若该功能实在需要解释，则使用 INFO或者？图标按钮，点击或者Hover后显示信息
