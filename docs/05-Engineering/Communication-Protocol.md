# 14 API 与组件通信协议（草案）

## 1. 通信对象

1. 客户端与应用服务。
2. 应用服务与模型 Provider。
3. Lumi Agent 与前端交互组件。
4. 用户组件事件与 Lumi Agent。
5. 学习记录与画像服务。

## 2. 关键操作

建议至少定义以下逻辑操作（具体 REST/WebSocket/gRPC 形式待工程评审）：
- 创建会话。
- 发送用户消息。
- 接收 AI 文本/组件输出。
- 创建组件。
- 更新组件属性或状态。
- 提交组件事件。
- 提交答案和解题过程。
- 获取学习画像。
- 更新学习目标/计划。
- 获取知识库版本与资源。

## 3. 事件处理要求

- 事件有唯一 ID。
- 事件有发生时间和顺序。
- 事件关联组件和上下文。
- 重试请求必须幂等。
- 关键事件先持久化再触发后续分析。
- 事件应区分草稿、阶段性操作和最终提交。
- 组件状态可恢复。

## 4. 安全约束

- 前端只渲染白名单组件类型。
- 不执行模型返回的任意脚本或 HTML。
- 函数表达式使用受限解析器。
- 对输入长度、事件频率和附件大小设置限制。
- 对用户数据和 API 凭证进行安全存储。
- 日志避免记录不必要的敏感内容。

## 5. 版本兼容

组件协议和事件协议必须有版本号。旧客户端遇到未知组件时，应显示可理解的降级提示，而不是崩溃。
