> This document is written in Chinese. The title and summary above are the English entry point.

- 版本：0.1.0
- 状态：初稿；范围需在原型评审后冻结
- 产品：Morrow Agent
- AI 助手：Lumi

## 1. 产品目标

帮助学习者达成学习目标。通过学习者画像、智能诊断、交互式教学、针对性训练和长期记忆，提升知识掌握程度与学习效率。

## 2. 首发范围

- 学科：陕西专升本高等数学。
- 内容范围：优先覆盖考试大纲中的主要章节和核心知识点；题目数量有限但覆盖面合理。
- 题目来源：真题、真题改编、AI 原创题。
- 题目模式：用户可选择训练偏好；Lumi 应解释不同模式的适用场景。
- 终端：Windows + Android。
- 完成目标：P2。P3 作为时间允许时的扩展目标。

## 3. 用户角色与主要场景

### 学习者
- 首次使用时选择学习阶段、学科、自评水平和目标。
- 通过诊断题及解题思路建立初始画像。
- 日常与 Lumi 对话、完成任务、查看知识点。
- 通过文本、语音和画板表达思路。
- 查看错题、薄弱点、掌握度和学习报告。
- 可纠正 AI 对自身水平的判断。

### 知识库贡献者/维护者
- 按统一格式提交知识点、知识关系、题目及解析。
- 通过审核和版本流程维护公共知识资源。

## 4. 功能需求

### 4.1 Dashboard

展示优先级：
1. 知识点掌握度概览。
2. 当前薄弱知识点。
3. 学习目标与进度。
4. 学习能力雷达图。
5. 学习趋势。

同时可展示今日任务、待复习内容、最近学习记录和 Lumi 建议。首页以学习仪表盘为主，而不是直接进入纯聊天页面。

### 4.2 Lumi AI 工作台

采用对话 + 可交互组件的工作台形态。Lumi 可以在对话中动态呈现：
- 选项、判断、排序等交互题型。
- 题目卡片、知识点卡片、例题卡片。
- 数学画板、公式编辑器。
- 函数渲染、坐标系和图形。
- 图表、能力雷达图、知识图谱。
- 学习目标、计划和任务卡片。

用户对组件的操作必须产生结构化事件并回传 AI。组件不是静态展示物。

### 4.3 首次使用与初始诊断

建议流程：
启动 → Lumi 欢迎 → 配置 AI Provider → 选择阶段/科目 → 自评水平 → 设置学习目标 → Lumi 初步交流 → 覆盖性诊断 → 疑似弱项追问 → 变式验证 → 诊断报告 → 用户确认/修正 → Dashboard。

诊断不要求每个用户固定完成所有轮次；根据证据和用户时间动态决定是否追加测试。

### 4.4 智能诊断

诊断粒度：
- 具体知识点。
- 错误类型。
- 能力维度。

诊断应区分：
- 已观察事实。
- AI 推测的可能原因。
- 已经通过验证的薄弱点。

对疑似前置知识问题，应生成针对性验证题，不应仅凭一次错误直接下结论。

### 4.5 专项训练与教学

用户可以选择训练时长，例如 5/15/30/60 分钟。Lumi 根据诊断结果选择直接讲解、引导提问、基础补充、例题演示或变式训练。教学风格可由用户设置，Lumi 也可依据表现动态调整。

### 4.6 学习目标与计划

通过交流了解用户真实目标，包括考试、目标分数、备考时间和题目难度偏好。对考试目标，可参考送分题、基础题、进阶题、高难题等层次拆解训练策略。

用户与 Lumi 共同制定、修改计划。Lumi 可根据学习进度和成果建议调整目标；计划调整应通知用户，不应无声地强制改变用户目标。

### 4.7 错题本

采用自动收录为主，用户可删除、修改和补充标签。错题记录应尽量保留：
- 原题与来源。
- 用户答案。
- 用户解题思路/过程。
- 正确答案与解析。
- AI 错误分析。
- 错误类型与关联知识点。
- 创建时间和复习历史。

### 4.8 学习画像与报告

掌握度采用 0–100 的展示尺度，但必须与置信度分开。掌握度依据应考虑：
- 解题思路是否正确。
- 是否独立完成。
- 变式题迁移能力。
- 延迟复习后是否仍能完成。
- 多次作答表现。

报告包括学习内容、题数、正确率、解题思路、薄弱点、掌握度变化和后续建议。用户可反馈讲解过难、过易或已理解。

### 4.9 模拟考试

MVP 支持简化版模拟考试。固定试卷、计时、交卷、统一评分和分析报告可作为基础能力；复杂组卷配置、考试管理等后续完善。

### 4.10 知识库

树形结构组织学科、章节和知识点；知识图谱表达前置依赖和关联关系。公共知识库与个人数据分离，资源包支持版本锁定和跟随最新版两种策略。

### 4.11 语音

暂定接入火山引擎体验接口作为候选方案。首发目标优先为语音转文字和 AI 语音回复；实时语音对话不作为当前必须项。需在开发前确认接口权限、免费额度、平台兼容、隐私与费用。

### 4.12 设置

- AI Provider 与模型配置。
- 数据管理与导入导出。
- 知识库版本管理。
- 语音设置。
- 学习偏好与教学风格。

## 5. 非功能需求

- 交互组件状态可恢复，重要操作不应因刷新/重连丢失。
- 用户个人学习数据与公共知识库分离。
- 组件事件应可追溯、可去重，避免重复回调造成重复记忆。
- AI 输出应能关联题目、知识点和证据。
- Demo 模式可重复演示，数据可重置。
- 网络或模型服务不可用时，应清晰告知用户并保留可恢复状态。
- 个人数据应提供备份/导出和删除能力；隐私策略需另行评审。

## 6. MVP 优先级

### P0：比赛版本必须完成
- 首次使用和 Provider 配置。
- Dashboard 基础版。
- Lumi 对话工作台。
- 交互组件框架及核心组件。
- 初始诊断与疑似弱项验证。
- 数学画板和函数渲染的核心演示能力。
- 错题自动收录及编辑。
- 基础学习画像与报告。
- 高数核心知识点与有限题库。
- 可重复的 Mock Demo。

### P1：时间允许
- 简化模拟考试完善。
- 更多交互组件。
- 更完整的知识图谱交互。
- 语音输入和语音回复。
- 更丰富的学习趋势分析。

### P2：后续版本
- 完整离线能力。
- 多学科完整知识库。
- 完整考试系统。
- 高级多 Agent 拆分。
- 社区资源审核与自动更新生态。
